# Архитектура и решения

## Цель

Минимальная задержка между концом фразы и началом обработки команды в Home Assistant Assist при почти нулевой
цене. Решение должно подходить не только владельцу (HA OS), но и другим: HA в Docker, другие Wyoming-клиенты.

Отправная точка — замеры в ha-yandex-station (2026-10-31, пайплайн «OpenAI»):

| Этап | Время |
|---|---|
| Ожидание тишины VAD в HA | ~0,7 с |
| OpenAI STT после конца речи (файл целиком) | 0,5–0,8 с |

Ожидаемый выигрыш — около 1 с: оба слагаемых заменяются определением конца фразы в Soniox (по смыслу и интонации,
настраивается) и мгновенным финальным текстом.

## Принятые решения

1. **Soniox `stt-rt-v5`** как движок: потоковый WebSocket, текст по словам, свой endpoint detection, $0,12/ч.
   Сравнение — [stt-comparison.md](stt-comparison.md).
2. **Wyoming-сервер, а не HACS-интеграция.** Работает с HA на любой установке (через встроенную интеграцию
   Wyoming) и с другими Wyoming-клиентами. По задержке варианты равны, т.к. HA всё равно передаёт в conversation
   только финальный текст ([ha-findings.md](ha-findings.md)).
3. **Отдельный репозиторий**, не внутри ha-yandex-station: со Станцией не связан, свои версии/issues/CI.
   HACS всё равно разрешает одну интеграцию на репозиторий, а приложений (add-ons) в одном репозитории может быть
   несколько — здесь одно.
4. **Сервер сам определяет конец фразы**: в `info` объявляет `requires_external_vad=False`. HA тогда не включает
   свой VAD и шлёт звук, пока не получит `transcript`.
5. **Три способа поставки**: приложение HA (магазин по ссылке на репозиторий), Docker-образ в GHCR, `pip install`.
6. **Без Soniox SDK**: WebSocket-протокол простой, хватит `aiohttp` (или `websockets`) — меньше зависимостей.
   [проверить: что лучше по размеру образа и стабильности]

## Поток одного запроса

```
Wyoming-клиент (HA)                 wyoming-soniox                         Soniox
  describe ───────────────────────▶ info (asr: requires_external_vad=False)
  transcribe {language} ──────────▶ открыть WS, отправить config ────────▶
  audio-start {16000, 2, 1}
  audio-chunk × N ────────────────▶ бинарные фреймы PCM s16le ───────────▶
                                    ◀── tokens (non-final / final) ───────
                                    ◀── token "<end>" (endpoint) ─────────
  ◀──────────────────────────────── transcript {text}
                                    пустой текстовый фрейм (конец аудио) ─▶
                                    ◀── {"finished": true}, закрытие ─────
  (клиент сам прекращает отправку звука, получив transcript)
```

- Текст = конкатенация `text` финальных токенов до `<end>` (сам `<end>` в текст не входит). Пробелы Soniox
  кладёт в токены сам [проверить].
- `audio-stop` от клиента раньше `<end>` (клиентский VAD, кнопка, конец файла) → отправить
  `{"type": "finalize"}`, дождаться `<fin>`, вернуть текст.
- Таймауты: нет `<end>` за N секунд после начала речи / общей длины → `finalize`. В HA 2026.10.4 при
  `requires_external_vad=False` своего ограничения у пайплайна может не быть [проверить], поэтому таймаут нужен
  в сервере обязательно.
- Пустой результат → `transcript` с пустым текстом (HA выдаст `stt-no-text-recognized`).
- Ошибка Soniox (`error_code`/`error_type`) → Wyoming `error` + лог с `request_id`.

## Настройки (опции приложения / CLI / env)

| Опция | Назначение | По умолчанию |
|---|---|---|
| `api_key` | ключ Soniox (CLI `--api-key` или env `SONIOX_API_KEY`) | — (обязательно) |
| `model` | модель | `stt-rt-v5` |
| `language` | язык, если клиент не прислал | из `transcribe`, иначе `ru` |
| `language_hints_strict` | не уходить в другие языки | true [проверить, нужен ли] |
| `context` | термины (имена устройств, зон) для лучшего распознавания | пусто |
| `endpoint_latency_adjustment_level` | 0–3, выше — быстрее конец фразы | 2 |
| `endpoint_sensitivity` | -1.0…1.0 | 0.3 |
| `max_endpoint_delay_ms` | 500–3000 | 1500 |
| `max_utterance_s` | страховочный таймаут | ~15 |

Стартовые значения endpoint-параметров — рекомендация Soniox для низкой задержки, подобрать на живых фразах.

## Будущее (не в MVP)

- Держать WebSocket тёплым (`keepalive`) и открывать сессию заранее — минус время на TLS/рукопожатие. Но Soniox
  считает деньги за всю длительность стрима, а не только за звук: нужно взвесить.
- Отдавать промежуточный текст через `transcript-start/chunk/stop` (`supports_transcript_streaming=True`), когда
  HA начнёт его читать.
- Автоподстановка контекста (имён устройств) из HA — только в отдельной HA-интеграции; Wyoming-сервер HA не видит.
