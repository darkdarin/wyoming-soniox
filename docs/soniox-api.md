# Soniox real-time WebSocket API: что нужно серверу

По документации https://docs.soniox.com (прочитано 2026-11-02). Живьём (2026-11-02) подтверждено: URL, заголовок
`Authorization: Bearer`, конфиг ниже, формат токенов, `<end>`.

## Живые замеры (2026-11-02, Mac → Soniox, синтезированная речь `say -v Milena`)

- Подключение + TLS: 0,3–0,55 с. Идёт параллельно с речью (звук копится в очереди), на задержку не влияет.
- `2 / 0.3 / 1500` (уровень / чувствительность / макс. задержка): «Поставь таймер на 5 минут.» — 0,6 с после
  последнего слова (по `end_ms` токенов; `scripts/transcribe.py` показывал 0,2 с, т.к. считает от конца файла,
  а `say` дописывает тишину); «Включи и свет на кухне.» — 2,0 с (синтезатор вставил «и», модель, видимо, ждёт продолжения, и
  срабатывает только `max_endpoint_delay_ms`).
- `3 / 0.5 / 1000` — 1,5–1,6 с на обеих; `3 / 0.5 / 500` — 1,0–1,2 с на обеих. То есть «агрессивные» настройки
  на синтетике хуже стандартных на «хорошей» фразе. Подбирать на живом голосе (этап 2).

## Станция → HA → Soniox (2026-11-02, настройки `2 / 0.3 / 1500`)

5 фраз, все слова распознаны верно, цифры числами («таймер на 30 секунд»).

- **Хвост wake word.** В начале фразы лишнее слово: «Всё, включи свет гостиной», «За выключи гирлянду…» — это
  конец «Али-са», хотя адаптер ha-yandex-station уже отрезает 300 мс (`spotter_tail_ms`). Вредно: «Всё, включи
  свет…» не совпала с локальным интентом и ушла в LLM (12 с ответа вместо мгновенного).
- **Звук приходит пачкой.** Адаптер в начале шлёт накопленный буфер быстрее реального времени (до ~3 с звука за
  долю секунды), поэтому задержку надо считать по времени прихода звука, а не по смещению в потоке.
- STT-этап в `pipeline_debug` (`stt-start` → `stt-end`, включает саму речь): 1,7–6,1 с. Локальные интенты
  (таймер) — 0,03 с после `stt-end`; LLM-агент — 3,4–12 с, это главное слагаемое.
- С исправленной метрикой (по времени прихода звука), 20 фраз: 0,4–1,1 с на обычных командах; 1,7–2,2 с на
  коротких («Да.», «Стоп.») — Soniox ждёт продолжения до `max_endpoint_delay_ms`.
- Первые замеры задержки после конца речи (по смещению, до исправления метрики): 0,7–0,8 с на длинных фразах,
  1,9–2,1 с на коротких («Отмени таймер.»).

## Подключение

- URL: `wss://stt-rt.soniox.com/transcribe-websocket`.
- Авторизация: заголовок `Authorization: Bearer <api_key>` **или** subprotocol `soniox-api-key` + ключ (не оба).
  Поле `api_key` в первом сообщении устарело; с 15 января 2027 такие подключения отклоняются.
- До стартового сообщения нужен `keepalive` минимум раз в 40 с, иначе закрытие с кодом `1001`.

## Первое сообщение (JSON-конфиг)

Обязательные: `model` (`"stt-rt-v5"`), `audio_format`. Для сырого PCM ещё `sample_rate`, `num_channels`.

Нам: `audio_format: "pcm_s16le"`, `sample_rate: 16000`, `num_channels: 1`.

Необязательные, полезные нам:

| Поле | Значение |
|---|---|
| `language_hints` | `["ru"]` |
| `language_hints_strict` | ограничиться подсказанными языками |
| `context` | `general`, `text`, `terms`, `translation_terms` — термины для лучшего распознавания |
| `enable_endpoint_detection` | `true` |
| `endpoint_latency_adjustment_level` | 0–3, по умолчанию 0; только v5 |
| `endpoint_sensitivity` | -1.0…1.0, по умолчанию 0.0; только v5 |
| `max_endpoint_delay_ms` | 500–3000, по умолчанию 2000 |
| `client_reference_id` | для отладки |

Рекомендация Soniox для низкой задержки: `endpoint_latency_adjustment_level: 2`, `endpoint_sensitivity: 0.3`,
`max_endpoint_delay_ms: 1500`. Чем быстрее конец фразы, тем выше шанс разрезать фразу на паузе и немного хуже
точность.

## Звук и завершение

- Звук — бинарные фреймы (base64 в текстовом фрейме тоже принимается).
- Конец звука — **пустой текстовый фрейм** (пустая строка). Пустой бинарный фрейм — просто пустой кусок звука.
- `{"type": "finalize"}` — финализировать всё отправленное; в ответ финальные токены и маркер
  `{"text": "<fin>", "is_final": true}`. Советуют слать после ~200 мс тишины и не чаще раза в несколько секунд.
- `{"type": "keepalive"}` — поддержание соединения [проверить точный JSON].

## Ответы

```json
{"tokens": [{"text": "…", "start_ms": 0, "end_ms": 0, "confidence": 0.9, "is_final": true}],
 "final_audio_proc_ms": 0, "total_audio_proc_ms": 0}
```

- Не финальные токены могут меняться; финальные приходят один раз и не повторяются.
- Конец фразы (endpoint detection): маркер `<end>`, всегда финальный, один раз в конце сегмента.
- В конце сессии `{"finished": true}`, затем сервер закрывает соединение.
- Ошибка: `error_code` (HTTP-статус), `error_type` (стабильный идентификатор), `error_message`, `more_info`,
  `request_id`; после ошибки соединение сразу закрывается.

## Лимиты и деньги

- До 300 минут звука на стрим; есть максимальная длительность сессии (ошибка 413 `max_duration_reached`).
- Открытые соединения, включая простаивающие, считаются в лимит соединений.
- Цена real-time: $0,12/ч (по токенам: $2/1M входных аудио-, $4/1M выходных текстовых токенов).
- Оплачивается вся длительность стрима, а не только обработанный звук — держать соединение открытым «про запас»
  стоит денег.
